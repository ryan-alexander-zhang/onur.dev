## Runtime Behavior

- The site still loads `https://unpkg.com/@tinybirdco/flock.js`.
- `flock.js` now writes explicitly to `analytics_events`.
- `data-stringify-payload="true"` is set explicitly so the Tinybird datasource schema matches the event envelope
  consistently.
- The script loads with `afterInteractive`, which is closer to the official starter kit's deferred-head snippet than the
  previous `lazyOnload` setup.

`flock.js` sends this event envelope:

- `timestamp`
- `action`
- `version`
- `session_id`
- `tenant_id`
- `domain`
- `payload`

For this repo, `payload` is stored as a JSON string in Tinybird. That matches the current `flock.js` default behavior
when `data-stringify-payload` is truthy.

## Tinybird Resources

The new Tinybird project defines:

- `analytics_events` datasource for raw events from `flock.js`
- `tracker` token with `APPEND` permission on `analytics_events`
- `dashboard` token with `READ` permission on the analytics endpoints
- `analytics_hits` helper endpoint for parsed `page_hit` events
- `current_visitors`, `top_pages`, `page_views_timeseries`, `top_sources`, and `web_vitals_summary` endpoints

## Environment Variables

Application runtime:

- `NEXT_PUBLIC_TINYBIRD_URL`
- `NEXT_PUBLIC_TINYBIRD_TOKEN`

Tinybird CLI / deploy:

- `TINYBIRD_HOST`
- `TINYBIRD_TOKEN`

Recommended usage:

- `NEXT_PUBLIC_TINYBIRD_TOKEN` should be the Tinybird `tracker` token generated by the deployed Tinybird project.
- `TINYBIRD_TOKEN` should be a workspace token used only for `tinybird build` / `tinybird deploy`.

## Commands

From the repo root:

```bash
bun run tinybird:info
bun run tinybird:build
bun run tinybird:deploy:check
bun run tinybird:deploy
```

## Deployment Notes

Validation and deployment completed on `2026-06-13` with:

```bash
npm run lint
cd tinybird && tinybird deploy --check
cd tinybird && tinybird deploy
```

The Tinybird main workspace now has these live resources:

- `analytics_events`
- `analytics_hits`
- `current_visitors`
- `top_pages`
- `page_views_timeseries`
- `top_sources`
- `web_vitals_summary`

Smoke test after deploy:

- Queried `current_visitors.json` successfully from Tinybird and received a valid `visits` response payload.

After `tinybird deploy` succeeds:

1. Open the Tinybird workspace.
2. Copy the generated `tracker` token value.
3. Put that value into `NEXT_PUBLIC_TINYBIRD_TOKEN`.
4. Redeploy the Next.js site.

The current repository changes handle the code-side integration and the Tinybird resource definitions. The only
remaining manual step is using the generated `tracker` token in the site's public environment.
